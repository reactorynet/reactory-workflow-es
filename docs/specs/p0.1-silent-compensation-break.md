## 1. Context (self-contained)

In `core/src/services/execution-result-processor.ts`, two methods were flagged. **Verification: only the first is a real bug; the
second (`compensate` `:196`) is already correct — see the correction box above.**

### Bug site 1 — `shouldCompensate` (line 257)

```typescript
// execution-result-processor.ts:257
if (step.revertChildrenAfterCompensation)
    return true;
```

This reads the *function reference* on `SagaContainer.revertChildrenAfterCompensation`. A function reference is always truthy, so this condition **always** evaluates to `true` regardless of what the step's logic actually intends. Every saga step with a non-null `compensationStepId` will trigger compensation logic unconditionally.

### ~~Bug site 2 — `compensate` (line 196)~~ — FALSE POSITIVE (already correct)

```typescript
// execution-result-processor.ts:196-198  — CORRECT AS-IS, do not modify
if ((!parentStep.resumeChildrenAfterCompensation()) || (parentStep.revertChildrenAfterCompensation())) {
    resume = parentStep.resumeChildrenAfterCompensation();
    revert = parentStep.revertChildrenAfterCompensation();
}
```

**This is not a bug.** All three references already invoke the methods with `()`. The original claim that
`parentStep.revertChildrenAfterCompensation` is "accessed as a property" here is incorrect — that mistake applies only to `:257`.
Leave lines 196–198 untouched.

The root cause is that `SagaContainer` (core/src/models/saga-container.ts) defines these as methods:
```typescript
public revertChildrenAfterCompensation(): boolean { return true; }
public resumeChildrenAfterCompensation(): boolean { return false; }
```
But the callers read them without `()`.

### User-visible impact

Saga compensation runs when it shouldn't, or uses wrong values for `resume`/`revert`. This silently breaks saga semantics — steps that should not be compensated get compensated (or vice versa), and compensation order is incorrect. The saga-compensation.spec.ts characterization test likely asserts incorrect values as a result.
