## 1. Context (self-contained)

### The bug

In `core/src/services/execution-result-processor.ts:compensate` (line ~232):

```typescript
let prevSiblings = workflow.executionPointers.filter(
    x => JSON.stringify(pointer.scope) == JSON.stringify(x.scope) 
    && x.id != pointer.id 
    && x.status == PointerStatus.Complete
);
```

Scope is `string[]`. Two arrays with the same elements in different orders produce different JSON strings:
- `[A, B]` → `"[A,B]"` 
- `[B, A]` → `"[B,A]"`

Even though both represent the same logical scope (the set of parent/ancestor pointers), they compare as unequal. While the current code always appends to scope in order (making this theoretically safe today), any future refactoring that adds/removes siblings out of order would silently break compensation scoping.

### Risk assessment

The invariant "scope is always appended in order" is undocumented and not enforced. A developer adding a `scope` element at an arbitrary index (e.g., `scope.splice(newIndex, 0, ...)` instead of `scope.push(...)`) would break this comparison without any type error or warning.

---

## 2. Goal

Replace the JSON.stringify-based scope comparison with a deterministic, order-independent comparison that:
1. Correctly identifies two pointers as having the same scope regardless of element order.
2. Is explicit about the comparison being set-based (not sequence-based).

## 5. Interface & data-model changes

None. This is a pure algorithmic fix in a private method body. No new types or interfaces needed.

### Helper to add

A small inline helper function within `compensate()` or as a private method:

```typescript
// Helper: compare two string[] arrays for set equality (order-independent)
const scopesEqual = (a: string[], b: string[]): boolean =>
    a.length === b.length && new Set(a).has(...b.map(v => v)) && new Set(b).has(...a.map(v => v));
// Simpler equivalent:
const scopesEqual = (a: string[], b: string[]): boolean =>
    a.length === b.length && a.every(v => b.includes(v));
```

## 6. Behavioural contract (numbered rules)

1. Scope comparison must be set-equality: two scope arrays are equal if and only if they contain the same elements, regardless of order.
2. The helper `scopesEqual(a, b)` returns `true` iff `a.length === b.length && a.every(v => b.includes(v))`.
3. A test exists that verifies pointers with scopes `[A, B]` and `[B, A]` compare as equal.

const scopesEqual = (a: string[], b: string[]): boolean =>

Replace `JSON.stringify(pointer.scope) == JSON.stringify(x.scope)` with `scopesEqual(pointer.scope, x.scope)`. No helper method needed on the class — a simple local constant or inline expression works since it's only called once.
