## 1. Context (self-contained)

### The issue

Two providers have wildcard-to-regex conversion for M9 search queries:

**Memory provider (`core/src/services/memory-persistence-provider.ts:263`):**
```typescript
private wildcardMatch(value: string, pattern: string): boolean {
    const escaped = pattern.replace(/[.+?^${}()|[\]\\]/g, "\\$&").replace(/\*/g, ".*");
    return new RegExp(`^${escaped}$`, "i").test(value);
}
```

**MongoDB provider (`providers/workflow-es-mongodb/src/mongodb-provider.ts:468`):**
```typescript
private escapeRegex(value: string): string {
    return value.replace(/[.+?^${}()|[\]\\]/g, "\\$&");
}
// Then in buildFilter (line ~430):
const pattern = "^" + query.workflowDefinitionId
    .split("*")
    .map((seg) => this.escapeRegex(seg))
    .join(".*") + "$";
filter.workflowDefinitionId = { $regex: new RegExp(pattern) };
```

### Edge cases to fix

1. **Empty pattern after split**: If the user searches for `*` alone, `split("*")` produces `["", ""]`, joining with `.*` gives `^.*$` — this is actually correct (matches everything). No bug here.

2. **Consecutive wildcards**: Searching `a**b` splits to `["a", "", "b"]`, joins to `^a..*b$`. The empty segment between consecutive `*` produces an empty `.*` which is a valid regex but semantically redundant (matches zero or more). No injection vulnerability here, just cosmetic.

3. **The `escapeRegex` character class `[\\]`**: In a character class, `\\` matches a literal backslash. This is correct for escaping the `\` metacharacter. However, the ECMAScript regex spec has other metacharacters in character classes that need attention: `]`, `[`, `^`, `-`. The current escape set handles most but not all.

4. **Cross-provider consistency**: The memory and MongoDB providers use slightly different approaches (one escapes-then-replaces `*`, the other splits-by-`*` then escapes). Both produce correct results for valid input, but the implementations diverge. For maintenance, they should share a common helper if possible, or at minimum have identical escaping logic.

## 2. Goal

1. Ensure both providers escape ALL ECMAScript regex metacharacters (full set: `.`, `\`, `^`, `$`, `*`, `+`, `?`, `(`, `)`, `[`, `]`, `{`, `}`, `|`).
2. Add a test that passes every common metacharacter as search input and verifies no regex injection occurs.
3. Document the wildcard syntax: `*` matches any sequence of characters (zero or more); all other characters are literal unless escaped by backslash.

## 12. Implementation notes (optional, non-binding)

The full ECMAScript regex metacharacter set to escape: `\ ^ $ . * + ? ( ) [ ] { } | -`

Recommended escaping function:
```typescript
const escapeRegex = (s: string): string => s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
```

Note the order: `\\]` must come before the closing `[` of the character class — this is correct in the existing code. The `-` metacharacter (literal inside character class when not between two chars) should also be escaped if present at the start or end, but since we're escaping it inside the class as `\-`, it's covered.
